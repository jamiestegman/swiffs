# Decisions

Append new decisions; replace one by writing a new one that says what it replaces.

| # | Decision | Why |
| --- | --- | --- |
| S1 | Swiffs ports upstream's algorithms, not its UI. `SwiffsCore`, `SwiffsHighlight` and `SwiffsEditor` follow `@pierre/diffs` releases, proven by golden fixtures. `SwiffsUI` is a native macOS design that matches upstream's look and skips its component, DOM and CSS changes | The algorithms take values and return values, so they port cleanly, and the fixtures prove it. The UI port brought the browser's assumptions without the browser: an element sizes itself and the page reflows around it. That left annotation sizing, threading and the public API without rules, so each fix was argued case by case and often repeated in several views |
| S2 | `SwiffsUI` is rebuilt, not refactored. The last commit with the ported UI is tagged `legacy-ui`. The new module replaces it in place, and reviewed pieces are carried over: `LineLayout`, palette and style, icons, cell drawing. Apps stay on their pinned revision until the new view covers their uses | The problems are in the module's shape, not in individual functions. A feature lived in up to four view classes, the API was a set of closure properties, the generics fell back to `Any`, and nothing said who measures an annotation. There are no users to migrate |
| S3 | The isolation map in [architecture](architecture.md#isolation). Core and Highlight hold `Sendable` values and `Mutex` caches. `HighlightService` alone runs background work, through an async `@concurrent` API. `SwiffsUI` is main-actor by default. `SwiffsUI` uses no `DispatchQueue`, `Timer`, `assumeIsolated`, `@unchecked Sendable`, `nonisolated(unsafe)` or `NSLock` | The port used six concurrency mechanisms, and nothing said what ran where. With one rule per module, the remaining cases follow from the rule |
| S4 | Hosted content is SwiftUI. Its host is measured synchronously with `NSHostingController.sizeThatFits(in:)` at the column's content width, then follows `onGeometryChange` reports. The document view sets every frame. Clients have no "height changed" call | Probe on macOS 26 in an `NSHostingView`-hosted window. `NSHostingView.fittingSize` and `intrinsicContentSize` gave 72 pt at widths 600, 300 and 150 for content needing 104, 136 and 232 pt. `sizeThatFits` gave those exact heights. Growing, shrinking and width changes were each reported and applied within one layout pass |
| S5 | One view, `DiffView` (AppKit), wrapped by `DiffList` (SwiftUI), over a list of items: diff, file and conflicted file. No `FileView`, `FileDiffView`, `FileStreamView`, `UnresolvedFileView` or per-view SwiftUI wrappers | A behaviour exists once, so a fix lands once. Before this, annotation rebuilding was fixed in one view and missing in another |
| S6 | The public API takes values diffed by id, and keys annotations by the client's id. Events go to one delegate protocol and to SwiftUI modifiers; selection and scroll position are bindings. Names follow the Swift API Design Guidelines, not upstream's | The port had 110 closure properties across 8 types and 16 casts through `Any`. Names like `renderHeaderPrefix` and `DiffsFileDiff` kept the JavaScript API's shape |
| S7 | `SwiffsUI` scope is in [requirements](requirements.md): what Manta uses now, what it has a named use for (conflicted files, growing files), and what waits (editing) | Each feature is kept for a use, so the API stays as small as its users |
| S8 | UI tests host the view inside SwiftUI, as apps do. They inject time, and never sleep | A sizing fix passed in a plain window and failed in Manta's SwiftUI-hosted one |
| S9 | Replaces the recycled tile views first planned. One flipped document view draws the rows that intersect its dirty rect; AppKit tiles its layer | Measured in Release on 300 files of 200 lines: the first frame took 55 ms against the ported view's 63 ms, and a scroll step 0.2 ms on average against 0.9 ms. Recycled tiles would add bookkeeping without a measured gain |
| S10 | `DiffList` gives hosted SwiftUI content the list's environment with `.environment(\.self, …)` | Content hosted in AppKit does not inherit SwiftUI's environment. Apps would otherwise re-inject every value their annotation views read |
| S11 | A conflicted file is a value. A conflict action reports the resolved file to the client, which passes it back as the item's content; the view does not resolve on its own | One source of truth: the client writes the file and stays in charge of what is shown |
| S12 | Items build rows only near the viewport and release them several viewports away, keeping their height. Estimates come from hunks and equal the built height when nothing wraps or is annotated. Small content an update shows is highlighted at once; everything else is highlighted ahead of scrolling, off the main thread | Updates and scrolling cost what is on screen, not the size of the branch. Highlighting while scrolling spiked a step to 39 ms; highlighting ahead brought the worst step to 1.5 ms |
| S13 | A file item whose new content starts with its old content is a growing file, not a new one. Its earlier lines keep their rows, layouts and highlighting; `HighlightStream`, an actor vended by `HighlightService`, tokenizes only the appended text and keeps the grammar state between appends | A file an agent is writing changes many times a second. Highlighting it whole each time costs the whole file per append; streaming costs the new text, and every visible character gets the colour whole-file highlighting gives it |
